# Вариант 2: Расширенный подход

## Архитектурный подход
Эффекты представляются как независимые сущности с собственной логикой применения, системой приоритетов и возможностью комбинирования. Вводится менеджер эффектов (`EffectManager`), который отвечает за применение, обновление и удаление эффектов. Эффекты могут взаимодействовать друг с другом (например, бафф защиты и дебафф уязвимости). Поддерживаются сложные типы эффектов: щиты, станы, отражение урона, поглощение и т.д.

## Изменения в типах данных
1. **Базовый интерфейс `Effect`** с расширенными полями:
   ```typescript
   interface Effect {
     id: string; // уникальный идентификатор
     name: string;
     description: string;
     icon: string; // название иконки для UI
     duration: number; // ходы
     maxStacks?: number; // максимальное количество стаков
     currentStacks: number;
     priority: number; // приоритет применения (0-10)
     type: 'buff' | 'debuff' | 'shield' | 'control' | 'special';
     // Модификаторы
     modifiers: {
       damageMultiplier?: number;
       damageReduction?: number;
       healingMultiplier?: number;
       energyGainMultiplier?: number;
       criticalChance?: number;
       dodgeChance?: number;
     };
     // Специальные свойства
     dotDamage?: number;
     hotHealing?: number;
     shieldAmount?: number; // величина щита
     isStun?: boolean; // оглушение
     reflectPercent?: number; // процент отражения урона
     onApply?: (target: Character, source: Character) => void;
     onTurnStart?: (target: Character) => void;
     onTurnEnd?: (target: Character) => void;
     onRemove?: (target: Character) => void;
   }
   ```
2. **Интерфейс `Character`** расширяется:
   ```typescript
   effects: Effect[];
   shields: number; // текущее значение щитов
   isStunned: boolean; // оглушён ли персонаж
   ```
3. **Интерфейс `Attack`** дополняется:
   ```typescript
   appliedEffects?: Effect[]; // эффекты, накладываемые атакой
   effectChance?: number; // шанс применения (0-1)
   ```

## Изменения в логике боя
1. **Новый редуктор `EFFECT_APPLY`**, `EFFECT_TICK`, `EFFECT_REMOVE`.
2. **Менеджер эффектов** как отдельный модуль, который:
   - Применяет эффекты в порядке приоритета.
   - Обрабатывает стаки (stacking) и обновляет длительность.
   - Вызывает колбэки `onTurnStart`, `onTurnEnd`.
   - Управляет щитами и контролем (станы).
3. **Модификация расчёта урона** в `ATTACK`:
   - Учитываются модификаторы из активных эффектов.
   - Проверяется наличие щитов перед вычетом HP.
   - Обрабатывается отражение урона.
   - Если цель оглушена (`isStunned`), она пропускает ход.
4. **Фаза обновления эффектов** в конце хода:
   - Уменьшение длительности.
   - Применение периодического урона/лечения.
   - Удаление истёкших эффектов.

## Визуализация
- **Панель эффектов** под карточкой персонажа с иконками, количеством стаков и таймером.
- **Анимации** для применения эффектов (всплывающие иконки, мерцание).
- **Индикаторы статусов** над персонажем (щит, оглушение, кровотечение).
- **Подсказки** (tooltips) с описанием эффекта.
- **Цветовое кодирование**: зелёные для баффов, красные для дебаффов, синие для щитов.

## Сложность реализации
- **Время**: 12-20 часов
- **Усилия**: средние/высокие, требуется создание менеджера эффектов и переработка логики боя.
- **Риски**: возможны ошибки в приоритетах и взаимодействиях эффектов.

## Гибкость и расширяемость
- **Добавление новых эффектов**: достаточно создать объект `Effect` с нужными свойствами и колбэками.
- **Комбинирование**: эффекты могут переопределять друг друга в зависимости от приоритета.
- **Модульность**: менеджер эффектов изолирован, что упрощает тестирование.
- **Ограничения**: сложные кастомные логики всё ещё требуют написания колбэков.

## Производительность
- Умеренное влияние из-за дополнительных вычислений и обходов массивов.
- Оптимизация: ограничение количества эффектов (например, 10 на персонажа), использование мемоизации.

## Конкретные примеры эффектов
1. **Щит Света** (бафф):
   - `shieldAmount: 20`, `duration: 3`, `icon: 'shield'`
   - Поглощает 20 урона перед HP.
2. **Оглушение** (контроль):
   - `isStun: true`, `duration: 1`, `priority: 9`
   - Персонаж пропускает ход.
3. **Отражение магии** (специальный):
   - `reflectPercent: 0.3`, `duration: 2`
   - Отражает 30% полученного урона обратно атакующему.
4. **Яд** (дебафф):
   - `dotDamage: 5`, `maxStacks: 3`, `duration: 4`
   - Каждый ход наносит 5 урона за каждый стак.
5. **Берсерк** (бафф):
   - `damageMultiplier: 1.5`, `damageReduction: -5` (повышает получаемый урон), `duration: 3`
   - Увеличивает урон на 50%, но снижает защиту.

## Изменения в коде
1. `src/types/game.ts` – полная переработка интерфейсов.
2. `src/effects/EffectManager.ts` – новый модуль менеджера.
3. `src/context/GameContext.tsx` – добавление действий для эффектов, интеграция с менеджером.
4. `src/components/BattleScene.tsx` – расширенная визуализация.
5. `src/components/EffectIcons.tsx` – новый компонент для отображения эффектов.
6. `src/db.ts` – добавление сложных эффектов к атакам.

## Плюсы и минусы
**Плюсы:**
- Богатая функциональность, поддержка сложных механик.
- Хорошая расширяемость за счёт менеджера эффектов.
- Улучшенный пользовательский опыт с визуальными индикаторами.

**Минусы:**
- Значительный объём работ.
- Повышенная сложность кода, труднее отлаживать.
- Риск снижения производительности при большом количестве эффектов.

## Рекомендации по использованию
Подходит для проектов, где эффекты являются ключевой игровой механикой и планируется много разнообразных способностей. Требует тщательного проектирования и тестирования.
