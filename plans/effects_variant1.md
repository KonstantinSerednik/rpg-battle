# Вариант 1: Минималистичный подход

## Архитектурный подход
Эффекты добавляются как простые модификаторы с фиксированной длительностью. Каждый эффект — это объект с предопределёнными полями, которые влияют на расчёт урона, лечения или энергии. Эффекты хранятся в массиве `effects` внутри объекта персонажа. Обработка эффектов происходит в редукторе `GameContext` при каждом ходе: уменьшается длительность, применяются модификаторы, удаляются истёкшие эффекты.

## Изменения в типах данных
1. **Интерфейс `Effect`** (уже есть в `src/types/game.ts`):
   ```typescript
   interface Effect {
     name: string;
     duration: number; // количество ходов
     type: 'buff' | 'debuff';
     modifier: {
       damageMultiplier?: number; // множитель урона (например, 1.2 = +20%)
       damageReduction?: number;  // абсолютное снижение урона (например, 5)
       healingMultiplier?: number;
       energyGainMultiplier?: number;
       dotDamage?: number;        // периодический урон за ход
       hotHealing?: number;       // периодическое лечение за ход
     };
   }
   ```
2. **Интерфейс `Character`** расширяется полем `effects: Effect[]`.
3. **Интерфейс `Attack`** дополняется полем `appliedEffects?: Effect[]` для атак, которые накладывают эффекты.

## Изменения в логике боя
В редукторе `GameContext` в обработчике `ATTACK` добавляются шаги:
1. **Применение эффектов атаки**: если атака имеет `appliedEffects`, они добавляются в массив эффектов цели (или атакующего).
2. **Расчёт модификаторов перед уроном**: перед вычислением урона/лечения собираются активные эффекты персонажа и применяются модификаторы.
3. **Обработка периодических эффектов (DoT/HoT)**: в начале хода каждого персонажа применяются `dotDamage`/`hotHealing`.
4. **Уменьшение длительности**: после хода каждого персонажа уменьшается `duration` на 1, эффекты с `duration <= 0` удаляются.

## Визуализация
В компоненте `BattleScene` рядом с карточкой персонажа отображается список активных эффектов в виде небольших иконок с подсказками (tooltip). Каждый эффект показывает оставшееся количество ходов. Используются простые CSS-стили (цветные рамки для баффов/дебаффов).

## Сложность реализации
- **Время**: 4-6 часов
- **Усилия**: низкие, изменения локализованы в основном в `GameContext` и `BattleScene`
- **Риски**: минимальные, так как не затрагивается архитектура

## Гибкость и расширяемость
- **Добавление новых эффектов**: требуется ручное добавление в `modifier` и логику применения.
- **Комбинирование эффектов**: эффекты складываются аддитивно (множители) или применяются последовательно.
- **Ограничения**: сложные взаимодействия (например, эффекты, меняющие логику игры) потребуют изменения кода.

## Производительность
- Незначительное влияние, так как массив эффектов небольшой (обычно ≤5 на персонажа).
- Расчёты производятся один раз за ход.

## Конкретные примеры эффектов
1. **Кровотечение** (дебафф):
   - `dotDamage: 3`, `duration: 3`
   - Каждый ход наносит 3 урона.
2. **Защита** (бафф):
   - `damageReduction: 5`, `duration: 2`
   - Снижает получаемый урон на 5.
3. **Усиление** (бафф):
   - `damageMultiplier: 1.3`, `duration: 2`
   - Увеличивает наносимый урон на 30%.
4. **Ослабление** (дебафф):
   - `damageMultiplier: 0.8`, `duration: 2`
   - Уменьшает наносимый урон на 20%.

## Изменения в коде
1. `src/types/game.ts` – расширение интерфейсов.
2. `src/context/GameContext.tsx` – модификация редуктора.
3. `src/components/BattleScene.tsx` – добавление отображения эффектов.
4. `src/db.ts` – добавление `appliedEffects` к некоторым атакам.

## Плюсы и минусы
**Плюсы:**
- Быстрая реализация
- Минимальные изменения в существующем коде
- Простота отладки и тестирования

**Минусы:**
- Ограниченная функциональность
- Сложные эффекты не поддерживаются
- Жёсткая привязка к структуре модификаторов

## Рекомендации по использованию
Подходит для проектов, где нужны базовые эффекты без глубокой кастомизации. Идеален для прототипирования или если время на разработку ограничено.
