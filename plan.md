# План разработки RPG Arena

## Введение
Цель — создать пошаговую браузерную игру в жанре фэнтези, где два игрока (или игрок против ИИ) выбирают персонажей и атаки, затем сражаются. План состоит из последовательных уникальных задач, последние две из которых — улучшения (новые функциональные фичи). Основной файл приложения — `App.tsx`. Для навигации между экранами используется состояние (stage) в контексте игры, а не React Router.

## Список задач

### 1. Инициализация проекта и настройка окружения ✅ ВЫПОЛНЕНО
- Создать React-приложение с TypeScript с помощью Vite.
- Установить зависимости: react, react-dom, typescript, vite, eslint, prettier.
- Настроить ESLint и Prettier согласно правилам проекта.
- Создать структуру папок: `src/components`, `src/context`, `src/types`, `src/utils`, `src/assets`. (Папки `hooks`, `data`, `pages` не создавались, так как не требуются.)

### 2. Навигация через состояние (stage) ✅ ВЫПОЛНЕНО
- React Router не используется, вместо этого навигация реализована через состояние `stage` в контексте игры.
- Определены стадии: `mode_select`, `p1_char`, `p1_attacks`, `p2_char`, `p2_attacks`, `battle`, `winner`.
- Обеспечена навигация между стадиями с сохранением состояния игры.

### 3. Использование существующих типов и данных ✅ ВЫПОЛНЕНО
- В проекте уже есть файл `src/db.ts`, содержащий интерфейсы `Attack` и `CharacterPreset`, а также массивы `ALL_ATTACKS` и `PRESETS`.
- При необходимости расширить эти интерфейсы (добавить поля для эффектов, модификаторов).
- Создать дополнительный интерфейс `GameState` для управления состоянием игры в отдельном файле `src/types/game.ts` (опционально, для улучшения структуры).

### 4. Реализация контекста состояния игры ✅ ВЫПОЛНЕНО
- Создать хук `useGame` или использовать Zustand/Redux для управления глобальным состоянием.
- Состояние должно включать: режим игры (PvP/PvC), текущую стадию, игроков, активного игрока, лог действий.
- Реализовать функции для изменения состояния: выбор режима, выбор персонажа, выбор атак, выполнение хода.

### 5. Компонент выбора режима игры (ModeSelection) ✅ ВЫПОЛНЕНО
- Создать компонент, который предлагает выбрать PvP (игрок против игрока) или PvC (игрок против ИИ).
- При выборе переходить к стадии `p1_char` с передачей выбранного режима.

### 6. Компонент выбора персонажа (CharacterSelection) ✅ ВЫПОЛНЕНО
- Отображать карточки всех доступных классов из `PRESETS`.
- При клике на карточку сохранять выбранного персонажа в состояние для соответствующего игрока.
- Переход к стадии `p1_attacks` (для игрока 1) или `battle` (для ИИ в режиме PvC).

### 7. Компонент выбора атак (AttackSelection) ✅ ВЫПОЛНЕНО
- Показывать список атак, принадлежащих выбранному классу (фильтрация по `className`).
- Разрешить выбрать ровно 4 атаки (минимум 1 ультимейт, максимум 1 ультимейт).
- Валидация: нельзя выбрать больше 4, нельзя выбрать одну атаку дважды.
- Кнопка "Готово" для перехода к стадии `p2_char` (PvP) или `battle` (PvC с автоматическим выбором ИИ).

### 8. Автоматический выбор для ИИ (PvC) ✅ ВЫПОЛНЕНО
- Если выбран режим PvC, второй игрок (ИИ) автоматически выбирает случайного персонажа и случайные атаки (4 штуки) без участия пользователя.
- После автоматического выбора сразу переходить к стадии `battle`.

### 9. Компонент поля боя (BattleScene) ✅ ВЫПОЛНЕНО
- Отображать двух игроков бок о бок с их карточками.
- В карточке показывать: имя, полоску HP, полоску ресурса, список выбранных атак.
- Подсвечивать карточку активного игрока.
- Для активного игрока отображать кнопки атак (обычные и ультимейты) с указанием оставшихся использований и стоимости ресурса.
- Для неактивного игрока (или ИИ) кнопки должны быть disabled.

### 10. Логика выполнения хода (handleAttack) ✅ ВЫПОЛНЕНО
- Реализовать функцию, которая принимает индекс выбранной атаки и применяет её к противнику.
- Рассчитывать изменение HP (урон или исцеление) и ресурса (прирост или затрата).
- Уменьшать количество использований атаки.
- Проверять, не достиг ли HP противника нуля (победа).
- Переключать активного игрока, если бой продолжается.
- Обновлять лог действий сообщением на русском языке.

### 11. Визуализация изменений (анимации) ✅ ВЫПОЛНЕНО
- Анимировать изменение полосок HP и ресурса с плавным переходом.
- Добавить всплывающие числа урона/исцеления над карточкой цели.
- Анимация кнопок при наведении и нажатии, пульсация ультимейт-атак, дрожание при получении урона.

### 12. Компонент экрана победителя (WinnerScreen) ✅ ВЫПОЛНЕНО
- При победе показывать экран с именем победителя, классом, оставшимся HP и ресурсом.
- Кнопка "Играть снова", которая сбрасывает состояние игры к началу (без перезагрузки страницы) и возвращает на стадию `mode_select`.

### 13. Тестирование основных сценариев ✅ ВЫПОЛНЕНО
- Протестировать вручную: PvP с полным циклом, PvC с ИИ, выбор атак, победа/поражение.
- Исправить обнаруженные баги.

### 14. Улучшение 1: Система эффектов (баффы/дебаффы) ✅ ВЫПОЛНЕНО
- Расширить интерфейс `Attack` для поддержки наложения эффектов.
- Добавить интерфейс `Effect` с полями: название, длительность (количество ходов), тип (бафф/дебафф), модификатор (например, +20% к урону, -30% к получаемому урону).
- Добавить в состояние персонажа массив активных эффектов.
- Модифицировать логика боя: при расчёте урона/исцеления учитываются модификаторы от эффектов.
- Реализовать уменьшение длительности эффектов после каждого хода персонажа.
- Визуализировать эффекты на карточке персонажа (иконки с таймером).
- Обновить ИИ для учёта эффектов при выборе атаки.
- Добавть видимость эффекта при выборе через плашку, которая активируется при наведении.
- Добававить на экране выбора атаки значок, чтобы было понятно, что атака имеет эффект.

### 15. Улучшение 2: Визуализация и графики (полировка интерфейса) ✅ ВЫПОЛНЕНО
- Использовать библиотеку `lucide-react` для добавления иконок к кнопкам и элементам интерфейса.
- Переработать дизайн карточек персонажей, добавить уникальные иконки для каждого класса.
- Внедрить плавные и выразительные анимации для атак (эффекты вспышек, дрожание экрана при получении урона).
- Реализовать адаптивный дизайн, улучшающий отображение на мобильных устройствах.
- Добавить тематические CSS-стили для каждого этапа игры (общий тёмный фон).
- Реализовать расширенную статистику с графиками: использовать библиотеку `recharts` для построения линейных графиков изменения HP и ресурса по ходам. Добавить кнопку "Показать статистику" после боя.
- Добавить индикатор критического удара (особый стиль текста с анимацией пульсации).
- Реализовать тёмную/светлую тему с переключателем, сохраняющим предпочтения в localStorage.
- Создать отдельные тематические градиентные фоны для каждого этапа игры (выбор режима, выбор персонажа, выбор атак, бой, победа).


## Заключение
Данный план позволяет последовательно создать игру RPG Arena с нуля, используя состояние (stage) для навигации и сохраняя основной код в `App.tsx`. Все базовые задачи (1-13) выполнены полностью. Улучшение 1 (система эффектов) полностью выполнено: реализованы расширенные типы данных, менеджер эффектов, интеграция с боем, визуализация иконок, подсказки при наведении, значки на экране выбора атак и обновлённый ИИ, учитывающий эффекты. Улучшение 2 (визуализация и графики) полностью выполнено: реализованы расширенная статистика с графиками (recharts), индикатор критического удара, тёмная/светлая тема с переключателем, отдельные тематические фоны для каждого этапа игры, а также все ранее запланированные визуальные улучшения и анимации. Каждый пункт представляет собой конкретную, уникальную задачу, что упрощает отслеживание прогресса.
